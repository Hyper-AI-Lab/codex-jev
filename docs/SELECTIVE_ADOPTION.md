# Jev Hardening and Selective Feature Adoption

Approved 2026-10-04. This extends `jev_audit_0.md`; it does not replace its
history or reopen completed work. Engineering closure and efficiency remain
separate. No new benchmark campaign is authorized.

## Contract

Keep one protected MCP/CLI integration. Adopt useful typed judgment patterns
and one global skill, not another provider client, automatic hook system,
model router, or conversation proxy. Jev judgments are advisory and cannot
authorize actions or establish that verification succeeded.

Preserve owner-selected models/effort, native workers, permissions, trusted
configuration, recovery history, and overlapping USD 10 validation/monthly/total
ceilings. One concurrent provider request, no daily count cap, quota retries,
key rotation, or provider substitution. Direct TypeSafe, pinned `jev-1.13.0`.
Cyber-Team application work and services, Google credentials/billing, schedules,
local inference, and the working Codex daemon remain untouched.

## Ordered Execution

1. Freeze source, installed release, ownership, recovery, accounting and findings.
2. Repair bounded history streaming, client compatibility, numeric coverage and
   exact native invocation attribution; unknown identities stay unattributed.
3. Unify provider authorization, redaction, reservation, transport and typed
   response validation for retrieval and judgments.
4. Close recovery/runtime findings, including SessionEnd and transient maintenance
   version queries, without replaying the consumed updater or restarting Codex.
5. Add bounded `judge_evidence` MCP/CLI classification, checks and rubric scores
   from authorized, hash-verified source ranges or existing evidence references.
6. Install one global `codex-jev` skill with pinned reference guidance; use useful
   batch judgments, not compulsory paid calls at every hook.
7. Verify offline, package and install reversibly, then verify the actual desktop
   connection, hashes, hooks and workspace isolation.
8. Observe two naturally occurring development tasks; publish sanitized results
   with native usage, overhead, correctness and explicit measurement gaps.

Each step appends commands, results, evidence and next action to the existing
Cyber-Team progress log. Required deviations are documented before execution.
