### Security Rebuild

The final dependency gate found
[GHSA-6qxp-vccf-f47h](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h)
in SDK 1.30.0. Upstream explicitly excludes stdio clients and MCP servers used here;
the vulnerable surface is HTTP OAuth client credentials. The SDK was nevertheless
pinned to the first patched release, 1.31.0, with no other dependency updates.
All 252 Node and 164 Python tests pass again. npm audit reports zero vulnerabilities;
checksum-verified Gitleaks 8.30.1 reports no leaks in the working tree. A synthetic
redaction fixture initially resembled a key and was replaced with an unambiguous
dummy marker, without weakening the redaction assertion or scan rules.

The patched immutable bundle passed the same bounded installed-protocol checks
in both workspaces. Its selections and judgments reused validated cache entries,
so this verification made zero additional provider calls and did not change the
ledger. These cache-only checks are not new live provider evidence. The actual
desktop loaded the initial adoption bundle before this patch; its final patched
hash and renewed hook callbacks still require verification.

Native input includes cached input; output includes reasoning. Native `revision`
identifies the collector that read a record, not proof of the runtime deployed at
the response timestamp. Recovered old observations cannot be counted as new-release
performance. Exact native task/turn receipt tests pass offline; private acceptance
clients intentionally do not manufacture native attribution.

The unchanged loopback OTLP collector remains active. Its observed completion
payloads still lack the required turn identity, so they are not added to elected
history totals. No source text, prompt or raw telemetry body enters reports.
